# Existing Simulation and RL Workflow Setup

This document outlines the progressively implemented end-to-end workflow for the Reinforcement Learning (RL) and Simulation components of the Adaptive Bandit Customer Service project, based on the current codebase and notebooks.

## 1. Data Processing and Auditing (Part 1)
*Implemented in `simulation_implementation_parts.ipynb`*

- **Data Ingestion:** Automatically discovers and ingests datasets from multiple sources, primarily Twitter (`twcs.csv`) and OpenAssistant.
- **Profiling & Auditing:** Runs a robust audit script extracting dataset metadata, including schemas, row counts, memory footprints, and cross-column missingness. 
- **Artifacts:** Generates inventory reports and summary statistics (`part1_file_inventory.csv`, `part1_missingness_sample.csv`, `part1_data_audit_report.md`).

## 2. Action Space Definition & Labeling Pipeline (Part 2)
*Implemented in `simulation_implementation_parts.ipynb`*

- **Canonical Action Space:** Defines a 7-action taxonomy for support agents:
  1. `Ask_for_Information`
  2. `Provide_Solution`
  3. `Affective_Repair`
  4. `Escalate_to_Human`
  5. `Close_with_Feedback`
  6. `Proactive_Update`
  7. `Set_Expectation`
- **Heuristic Labeling:** Extracts agent-specific conversational turns and classifies them using robust regex and pattern-matching rules with confidence weighting.
- **LLM-Based Annotation Generation:** Utilizes a local fast-batch LLM pipeline (`qwen3:4b` via `ollama`) to generate pseudo-labels for large swaths of the unstructured dataset to validate and compare against heuristic baselines. 

## 3. RAG-Grounded Metric Imputation (Parts 3 & 4)
*Implemented in `simulation_implementation_parts.ipynb`*

- **Metric Alignment:** Handles discrepancies between unstructured datasets (Twitter) and structured ones (OpenAssistant) by imputing critical RL metrics like `quality`, `sentiment_score`, and `frustration_proxy`.
- **Few-Shot RAG Calibration:** Uses extreme low/high score exemplars (anchors) from the OpenAssistant database to provide in-context learning to the LLM for accurate and normalized synthetic metric scoring.

## 4. Environment & Simulator Core (Part 5)
*Implemented in `rl_environment.py` & `simulation_implementation_parts.ipynb`*

- **CustomerSupportEnv (MDP):** Defines the RL Environment tracking turn-by-turn states (sentiment, frustration, escalation likelihood) bound by SaaS business tier economics (`Enterprise`, `Business+`, `Pro`, `Free`) and mapped to specific customer personas (`Cooperative`, `Impatient`, `Escalation-prone`, `Silent-dropoff`).
- **Shaped Rewards Function:** Calculates dense rewards balancing operational costs (escalation fees, turn friction) against terminal outcome profits and sentiment improvements.
- **OllamaRAGSimulatorEnv:** An evolved, advanced LLM-driven variation of the environment where state transition dynamics (how user frustration/sentiment changes after an agent action) are dynamically generated by an LLM interpreting the historical RAG context, replacing static mathematical multipliers.

## 5. Baseline Simulation & Validation Framework (Part 8)
*Implemented in `simulate_and_validate_rl.ipynb` & `simulation_implementation_parts.ipynb`*

- **Random Policy Generation:** Generates multi-turn episodic interactions using a random policy agent to evaluate the base constraints and properties of the environment prior to Bandit/PPO training.
- **SimulatorValidator Pipeline:** A 5-dimension test suite evaluating:
  1. Statistical Fidelity
  2. Transition Accuracy
  3. Persona Behavior Fidelity
  4. Business Validity
  5. Ethics and Risk Controls
- **Visual Analytics:** Evaluates state distributions across large episodic batches (e.g., 1000 simulated conversations), plotting metrics such as conversation length distribution, escalated vs. resolved outcome ratios segmented by business tier, and multi-turn frustration tracking by persona.
